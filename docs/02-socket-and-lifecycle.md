# 实验二：亲手处理 HTTP 字节与资源

运行 `scripts/run.ps1 -Mode socket`，再运行 `scripts/run.ps1 -Mode client`。客户端会打印完整响应，使状态行、响应头、空行和正文都可观察。

## 有意限定协议范围

Socket 版本接受 HTTP/1.1、origin-form 路径、GET、一个非空 Host、CRLF 行结束。只处理一条请求，发送响应后关闭连接。

| 边界 | 行为 |
| --- | --- |
| 请求行 | 最多约 2048 字节；超限返回 431 |
| 所有请求行与请求头 | 总计最多 8192 字节、最多 32 个字段 |
| 请求体 | 不接受；非零 Content-Length 返回 400，Transfer-Encoding 返回 501 |
| 重复请求头或查询参数 | 返回 400，避免不明确的解释 |
| 其他方法 | 405，Allow: GET；HEAD 仅返回响应头 |
| 请求头超时 | 从接受连接起约 5 秒，包括排队时间，返回 408 |
| 未知路由 | 404 |
| 容量耗尽 | 直接关闭新连接；不承诺发送 503 |

不支持持久连接、流水线、分块正文、代理绝对 URL、HTTP/2、HTTP/3。练习时不要把它直接放到公网或代理之后使用。

## 请求如何到达 Controller

`Handler` 先读取有界的 CRLF 行，校验协议头，再解析 URI 和查询串。参数按 UTF-8 解码，`+` 代表空格；缺少等号、重复参数、控制字符和无效编码都会被拒绝。

解码器使用 REPORT 模式，非法字节不会被静默替换。合法的 `%EF%BF%BD` 本来就代表 U+FFFD，应正常解码，再交给业务查询；不能仅凭结果中出现该字符就判定编码错误。

`web.properties` 只由项目本地配置控制，把 `index` 映射到 `controller.IndexController`。配置在启动时读入不可变映射，Controller 每次请求新建。请求路径不能指定任意 Java 类。

`IndexController → UserService → UserDao` 保留了分层例子。DAO 返回固定的 `My Sweetheart` 演示用户：缺少 username 为 400，查不到为 404。公开结果不包含密码。这里没有实现身份认证。

## 谁负责关闭资源

| 资源 | 所有者 | 释放点 |
| --- | --- | --- |
| ServerSocket | Server | close() |
| 已接收及排队 Socket | Server 跟踪，Handler 使用 | 请求完成或 Server.close() |
| 接受线程 | Server | 关闭监听器后 join |
| 有界线程池 | Server | shutdownNow + awaitTermination |
| 配置输入流 | MyServerReader | try-with-resources |

线程池默认 4 个工作线程和 16 个排队位置，不再每个连接无限制地创建线程。关闭时先停止接受新连接，再关闭活动与排队 Socket，最后等待线程退出。排队连接也必须释放，否则停止服务仍会残留资源。

即使调用线程已有中断标志，close() 也会继续限时等待资源退出，最后恢复标志，供上层感知取消。把 InterruptedException 直接抛出会跳过剩余清理；直接吞掉则会丢失取消信号。这条契约同时适用于 JDK 和 Socket 两种服务。

`Handler` 的请求头期限用单调时钟计算；每次读取只使用剩余时间。客户端不断发一个字节不能无限重置期限。过载时接受线程不会阻塞写错误页面。

JDK 版本使用另一套边界：最多 64 个连接、4–8 个工作线程、32 个排队任务；任务排满时采用 CallerRunsPolicy，分发线程参与执行并形成背压。它不是严格的每秒请求限流器，也不承诺过载必返回 503。超时检查由 JDK 定时器执行，不能视作精确到毫秒的截止线。

## 可继续做的练习

- 修改控制器，添加一个无副作用的路由，并测试未知路由和缺失参数。
- 用测试客户端先发一半请求头，观察 408，再验证其他请求仍可完成。
- 比较连接关闭与 Keep-Alive 的不同；真正加入持久连接前，先为消息边界和多个请求设计测试。
