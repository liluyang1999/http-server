## 如何复验

```powershell
.\scripts\build.ps1 -Test
```

这里运行真实 TCP 和 TLS，不需要 JUnit 或新增库。TLS 测试用已安装 keytool 生成一次性证书，结束后清理临时文件。生命周期测试使用临时端口，不占固定 8081/9999。

当前套件包含 74 项 Java 行为检查（30 + 5 + 6 + 8 + 25），以及 17 项启动参数检查。后者用脚本内 Java 替身验证是否进入启动路径，不创建网络服务；实际网络行为由 Java 集成测试及成品启动检查覆盖。

成品复核使用构建出的 JAR，从项目以外的工作目录启动，验证网页/路由配置随包读取、HTTP/HTTPS 成功与错误请求、Socket 客户端，以及非法 CLI 参数；证书测试还验证未受信证书和错误主机名会被拒绝。2026-09-18 的独立验收完成 152 次断言，同一工具链连续两次构建的 JAR SHA-256 一致。

额外浏览器流程：启动构建出的 JAR，操作 GET/POST、除零错误、键盘重试与窄窗口布局，再停止服务。这些操作已在同日首轮验收执行；本轮网页源文件未变，重新核对了 JAR 中的网页与已验收源码一致。详细请求及清理记录保存在工作区交付报告。

已运行的编译器警告检查不能替代完整静态安全分析。没有执行公网压测、代理兼容矩阵、多 JDK 矩阵、远端 CI 或生产发布。原有 Gson 2.8.9 本次未升级，未以此声明供应链安全审计通过。

## 练习顺序

1. 先故意写错 Content-Length，观察客户端的表现，再恢复并用测试锁定正确字节长度。
2. 在 Arithmetic 中添加一种运算，为正常和异常输入分别写回归测试，再扩展 HTTP 路由。
3. 为未知字段设计明确契约：严格拒绝和忽略各有什么兼容性代价？
4. 尝试让 Socket 版本的 HEAD 返回成功资源的元数据（当前返回 405），同时确保任何状态下都不写正文。
5. 设计可取消的长计算。先明确连接、任务与取消信号的所有者，再考虑增加线程数。

不要把“测试绿色”理解为支持全部 HTTP 语义；教学实现的协议范围在 docs/02-socket-and-lifecycle.md 中有明确约定。
